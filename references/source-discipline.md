# 取材纪律

## 信息源

**只用官方网页。** 由 agent 自己的 WebSearch / WebFetch 抓取。

- 本 skill **不调用任何 API，不需要任何 key，不注册任何服务，没有 scripts/ 目录**。
- **不抓社交媒体**（twitterapi.io / X / 微博等一律不用）。这是刻意的取舍：
  社交源时效性强但信噪比低，且需要付费 key。官方源足够回答「这是什么、怎么用」。

## 官方术语优先源（Tier 1）

解释**官方术语**时，先查 `assets/official-sources.md` 的路由表，优先用 WebFetch 去对应官网取一手定义；
概念**不在那 5 个网址覆盖范围内**，才走下面的通用抓取顺序。

> 这是用户明确指定的硬优先级：**官方术语 → 官网优先；超出官网 → WebSearch 兜底。**
> 5 个官网覆盖 OpenAI API / LangChain / HuggingFace Agents / Claude Academy / Microsoft AI Decision Framework，
> 已能覆盖绝大多数核心 AI·Agent 术语（Agent、MCP、RAG、Tool、LLM、Function-calling、Computer Use…）。

## 抓取顺序

按下列优先级取，取到足够支撑关键句层即可停：

1. **一手官方**——官方文档、官方博客、RFC / 规范原文、项目 README、官网产品页
2. **权威二手**——标准机构、知名厂商技术博客、维基百科（仅用于定义与沿革）
3. **高质量解读**——知名技术媒体、有署名的深度文章

**不要**引用：内容农场、无署名聚合站、纯 SEO 页面、AI 生成的二手站。

## 最小取材量

动手写之前，先确认手上至少有：

- 1 个**定义**（一句话说清它是什么）
- 2–4 条**可支撑关键句的事实**（对应 R2 的关键句层）
- 若概念有争议/局限，至少 1 条**反方或局限**的出处（对应 R7 不遗漏）

少于这个量 → 走下面的降级话术，**不许脑补凑数**。

## 引用格式

- 每个事实性断言后面必须带 markdown 链接：`[来源](url)`
- 链接必须来自实际抓取到的页面。**一个都不许编造**。
- 同一事实多个来源时，优先引一手官方；二手来源用于补充「别人怎么看」。
- 关键句层每条至少 1 个链接；支撑层每条至少 1 个链接。

## 降级话术（素材不足时照抄，禁止改写发挥）

| 情况 | 照抄这句 |
|---|---|
| 完全搜不到 | 「这个概念我没找到足够的公开资料，建议换个说法，或提供更具体的上下文（比如它在哪个产品/文档里出现）。」 |
| 只找到定义，找不到「为什么最近火」 | 「目前公开资料只讲清楚了它是什么，没找到关于『为什么现在被讨论』的可靠来源——这部分我不猜。」 |
| 只有二手来源，没有官方 | 「没能找到一手官方文档，以下内容来自第三方解读，可信度较低，建议以官方文档为准。」 |
| 概念太新，只有零散讨论 | 「这个概念还很新，公开资料零散且互相矛盾，以下是能确认的部分：…」 |
| 用户追问的内容搜不到 | 「这部分我没搜到可靠来源。要我基于已有资料做推断吗？（会明确标注是推断）」 |

## 硬规则

1. **不许编造**。抓不到的信息就不写，用降级话术。金字塔结构的完整性不能靠脑补补上——
   宁可少一层，也不要塞一层假的。（对应 R7 的「不遗漏」是指已知范围内的不遗漏，不是凭空补）
2. **不许用素材堆砌冒充思想**。抓到一堆事实后必须先做分组（R5 单一名词检验）和排序（R6），
   不能直接罗列。原始事实素材本身不是「思想」。
3. **时序类断言必须带时间锚点**。「最近」要写成具体年月；「大幅」要写成具体数字。
   做不到就删掉这个断言（对应 R11 行动结果必须可判定）。
4. 抓到的官方页面若与用户描述冲突，以官方为准，并明确指出差异。
