## 总纲（p9 原文）

> 金字塔原理的基本结构是：**结论先行，以上统下，归类分组，逻辑递进**。
> 先重要后次要，先总结后具体，先框架后细节，先结论后原因，先结果后过程，先论点后论据。
> 搭建金字塔结构的具体做法是：**自上而下表达，自下而上思考，纵向总结概括，横向归类分组，序言讲故事，标题提炼思想精华。**

四原则定义（p302）：
- **结论先行**：每篇文章只有一个中心思想，并放在文章的最前面。
- **以上统下**：每一层次上的思想必须是对下一层次思想的总结概括。
- **归类分组**：每一组中的思想必须属于同一逻辑范畴。
- **逻辑递进**：每一组中的思想必须按照逻辑顺序排列。

# 核心规则 R1–R8（所有模式一律适用）

## R1 结论先行

- **定义**：每篇文章只有一个中心思想，并放在最前面（p302）。「这种形式还能保证你将思想的重点一定放在文章的最前面」（p37）。
- **判定问句**：① 全文能否用**一个**句子概括？② 该句是否是**含主语和谓语的完整句**？③ 该句是否在正文第一段之前/之中（而非结尾）？④ 全文是否**只有一个**中心思想——收尾的「所以」行是结论的**推论或行动**，而不是另一个互不相干的新结论？四个必须全 yes。
- **失败签名**：无总起句直接铺陈；结尾才出现「因此／总之」；首句是类比（「XX 就像…」）或定义（「XX 是一种…」）而非断言；**双结论**——「所以」行引入了一个**主张对象不同**的新结论（例：结论「MCP 值得接入」+ 所以「建议改用 A2A」＝换了主张对象，违规）。
- **⚠️ 不算双结论的情形**：「所以」行是同一对象上的**推论或行动**时不违规。
  例：结论「Agent 会取代传统工作流」+ 所以「尽快把现有流程迁过去」——同一对象的推论，**通过**。
- **修复动作**：把结论句提至最前，改写成**含判断动词的断言**。禁止类比开场、禁止定义句开场。若存在双结论，删掉较弱的那个，或把「所以」行改写成与结论同一对象的推论/行动。
- **正例**：「RAG 只是过渡方案，不能替代长上下文，因为它治标不治本。」
- **反例**：「RAG 就像是给 AI 配了一个随身图书馆。」（是比喻，不是结论）
- **出处**：p22、p26、p37、p302

## R2 思想是完整句，不是类别标签

- **定义**：思想是「向受众发出新信息并引发受众疑问的语句」（p31）。「标题应呈现某种思想、观点或论点，而不是只说明要讨论问题的类别」（p52）。「不要用『我们的发现』或『结论』这类的标题」（p52）。
- **判定问句**：① 这句是**完整句**（有主谓）还是**名词/名词短语**？② 读者读完是否会被引发「为什么／怎么做／你怎么知道」？③ 删掉它读者会不知道少了什么吗？答「名词短语／不引发疑问／删了也行」→ 违规。
- **失败签名**：小标题写成「背景」「基本概念」「优势」「应用场景」；或正文是「某公司存在5个问题」这类只预告类别的句子。
- **修复动作**：把每个名词性标签改写为断言句（「XX 导致 YY」而非「XX」）。
- **正例**：「检索质量决定 RAG 的上限」
- **反例**：「检索部分」
- **出处**：p31、p51-52、p65-66

## R3 禁止「缺乏思想」的句子

- **定义**：Minto 点名三类——「该公司应当确立3个目标。该公司存在2个问题。我们建议进行5项改革。」「这些句子被称为『缺乏思想』的句子，是因为这些句子实际上并没有概括其下一层次思想的精华，而只是说明了将要讨论的思想属于哪一类思想」（p141）。
- **判定问句**：把句中的**数量词和数字删掉后**，该句是否仍然陈述了一个**可争议的判断**？否 → 违规。
- **失败签名**：「RAG 有三大优势」「使用 MCP 要注意5点」「这个概念有4个特点」。删掉数字后变成「RAG 有优势」——完全不可争议。
- **修复动作**：说出这些项的**共同点所隐含的意义**。问自己「为什么我只列出这些，而不列其他？」（p175）
- **正例**：「RAG 的成本几乎全耗在检索环节，因此优化检索比分块调优更划算。」
- **反例**：「RAG 有三大优势：…」
- **出处**：p109、p141、p143、p167、p308

## R4 以上统下

- **定义**：「纵向：文章中任一层次上的思想必须是其下一层次思想的概括」（p27）。「你不能将5个关于金融的句子和1个关于网球的句子组织在一起，因为它们之间的关系难以用一个概括性的句子表达」（p26）。
- **判定问句**：① 上层句去掉后，下层**≥半数**要点是否仍对应同一件事？② 下层能否**倒推**生成上层那句话？
- **⚠️ 判定门槛（防误判）**：**只有下层 ≥半数要点与上层主题无关时才判违规。**
  「论证力度不足」＝同主题但不够有力，**不判违规**——那归 R3（空壳概括）和 R5（范畴混杂）管。
  孤儿要点只有 1 条、其余都相关时，判**通过**（剔除那 1 条即可，不是结构性问题）。
- **失败签名**：上层说「现状堪忧」，下层却**全在**讲历史沿革；上层说「三个原因」，下层 2/3 却是具体安装步骤。
- **修复动作**：二选一——改下层（剔除不属于该概括的要点）或改上层（写出真正涵盖下层的概括句）。
- **正例**：上层「RAG 是过渡方案」→ 下层三条**全是**支持「过渡性」的论据
- **反例**：上层「RAG 是过渡方案」→ 下层混入「RAG 的安装方法」
- **出处**：p26-28、p302

## R5 单一名词检验（归类分组）

- **定义**：「检查你将思想分组的一个简便方法，就是你是否能够用**单一名词**表示该组的所有思想」（p28）。「如果某组思想中的第一个思想是做某件事的一个原因，那么该组中的其他思想也必须是做同样一件事的其他原因」（p28）。
- **判定问句**：能否为这组**全部**要点找到**同一个实质性的**复数名词？能 → 通过。需要用「和／以及」才能概括 → 违规。
- **⚠️ 与 R3 的分工（勿冲突）**：单一名词必须是**实质性**的——原因／代价／步骤／条件／风险／差异／局限……
  **「优势」「特点」「要点」「方面」这类空类别词不算通过**，否则会与 R3（禁止「有三大优势」式空壳）自相矛盾。
  举例：「答案更准 / 能引用来源 / 不用重训」——R5 看似乎能叫「三个优势」，但「优势」是空类别词，
  R3 判定其删掉数量词后不可争议 → **以 R3 为准，判违规**。正确做法是把它们换成实质名词，
  如「三个代价的规避」或「三种能力的补强」。
- **失败签名**：一组里混入「原因 + 步骤 + 问题描述」；或用过于宽泛的词强行打包——「这样的概括过于宽泛，难以说明该组思想之间的逻辑关系」（p27）。
- **修复动作**：拆组（按范畴重分）或提高抽象层次后再检验；把空类别词换成实质名词。
- **正例**：「成本高 / 延迟高 / 运维重」→ 同属「三个代价」
- **反例**：「成本高 / 先装依赖 / 团队抗拒」→ 原因+步骤+问题，三不像
- **出处**：p27-28、p35-36、p302

## R6 无逻辑顺序即错误

- **定义**：顺序只有三种——「时间顺序：通过设想某一流程得出的思想。结构顺序：通过评论某一结构得出的思想。程度顺序：通过按程度或重要性不同分组得出的思想」（p306）。「**如果你在某一组思想中找不到以上顺序，说明这些思想之间不存在逻辑关系，或者你的思考还不周全**」（p306）。
- **判定问句**：① 当**步骤**依次执行，语义成立吗？→ 时间。② 能画成**示意图**并自上而下、自左而右描述吗？→ 结构。③ 能指出**同一特性的不同程度**并排出强弱吗？→ 程度。三个全否 → 违规。
- **⚠️ 并列理由／优势的适用口径**：「程度顺序」按 Minto 的定义就是「按程度或**重要性**不同分组」。
  因此**同类并列的理由或优势，只要能说出「哪条最重要」并按重要性递减排列，即算程度顺序、通过**。
  不要因为「打乱无损」就一律判违规——并列优势本来就没有时间或结构关系，强行要求只会制造假阳性。
  只有**既说不出强弱、又标不出时间与结构关系**时，才判违规。
- **失败签名**：随机罗列「首先…其次…再次」，互换位置完全等价**且说不出哪条更重要**（打乱无损 + 无强弱 = 无序）。
- **修复动作**：三问全否 → **该组解散**，逐条降级为素材，按划分依据重建，不得强行并列。
- **正例**：「先装依赖 → 再配 MCP server → 最后验证连通」= 时间顺序
- **反例**：「成本高 / 团队抗拒 / 延迟高」随意排列，打乱无损
- **出处**：p28-29、p114、p306

## R7 MECE——不重叠、不遗漏

- **定义**：「各部分之间相互独立（mutually exclusive），没有重叠，有排他性。所有部分完全穷尽（collectively exhaustive），没有遗漏。这两个要求简称为分组的 MECE 原则」（p121）。
- **判定问句**：① 任取两项 A、B，能否构造出一个实例**同时落入** A 和 B？能 → 重叠。② 出现「其他」兜底了吗？③ 能否举出一个属于上层范畴但**不落入任一项**的实例？能 → 遗漏。
- **⚠️ 遗漏子问句的适用条件（防误判）**：第 ③ 问**仅在上层是「范畴」时启用**（如「成本分为三类」「改动涉及四个部门」——
  范畴可穷尽，遗漏可证伪）。**若上层是「结论」**（如「MCP 值得接入」），上层不是范畴，
  任何理由清单都能被再举出第四条，遗漏不可证伪 → **该项不适用，直接判通过**。
- **失败签名**：要点之间互相包含；或用「其他」兜底（「其他」= 承认没想清楚）。
- **修复动作**：按 p130-131 把每条改写为其**结果**（高成本／法律限制／被迫降价…），再对号入座到一张现成的树形图；树上空缺分支即遗漏点，两条落进同一叶子即重叠点。
- **正例**：「轮胎部 / 硬件部 / 体育设备部」相加即全部（p122）
- **反例**：「投资多 / 研发费用高」（两者同属高成本，重叠）
- **出处**：p121-124、p144、p308

## R8 纵向问答——疑问词锁定回答类型

- **定义**：读者对任一表述必然产生疑问——「为什么会这样」「怎样才能这样」「为什么你这样说」，作者必须在**下一层次横向地回答**（p31-32）。**回答类型被疑问词锁定**：「针对『为什么』之类问句的回答必须是『原因』」（p44）；「针对疑问词为『如何』的问句，回答必然是有关『步骤』」（p76）。
- **判定问句**：① 上层句能引发至少一个疑问吗？② 疑问词是 为什么／如何／你怎么知道／哪一个？③ 下层**所有**要点是否属于该疑问词锁定的那一类（为什么→原因；如何→步骤；你怎么知道→证据；哪一个→评估标准）？
- **失败签名**：上层引发「为什么」，下层却给「步骤」；或下层重复上层结论本身，不提供新信息。
- **修复动作**：按疑问词替换下层要点类型；重复项删除。
- **正例**：「RAG 是过渡方案」→（为什么？）→「因为①上下文窗口在变大 ②检索本身有天花板 ③工程复杂度不划算」← 三条**全是原因**
- **反例**：「RAG 是过渡方案」→「①上下文在变大 ②先装依赖 ③某公司已上线」← 原因+步骤+案例，类型错乱
- **出处**：p31-35、p44、p53-54、p76、p303

# 论证层 R9–R11（concise / detailed / mindmap 适用）

## R9 SCQA 序言，且只含读者已知信息

- **定义**：序言「必须先介绍读者熟悉的某些『背景』，说明发生的『冲突』，并由此引发读者的『疑问』，然后针对该『疑问』给出『答案』」（p56）。关键约束：**「序言的目的只是告诉读者一些他们已经知道的信息」**（p53）；「序言中不应含有读者需要证明后才能接受的信息，例如，不应当含有图表」（p74）。
- **判定问句**：① S（背景）、C（冲突）、Q（疑问）、A（答案）四要素是否齐全（Q 可隐含）？② 删掉 C 后读者还会问 Q 吗（若还会 → C 无效）？③ 序言里是否出现了需要**数据／推导／引用**才能成立的新信息（是 → 违规）？④ S 句是否把读者「锁定」在特定的时间和空间（p59）？
- **失败签名**：序言里塞数据表、引用、新术语定义、历史叙述；或只有背景没有冲突（读者问不出问题）。
- **修复动作**：把需要证明的内容下移到正文支撑层；把纯背景上移到序言；术语定义允许留在序言（p74）。倒推法：「为什么读者应该知道这些思想？肯定是因为这些思想能够回答某个问题」（p74-75）。
- **正例**：「大模型的上下文窗口已经从 4K 涨到百万级（S）。但企业仍不敢把全部知识塞进去（C）。RAG 还有必要吗？（Q）→ 有必要，但只是过渡（A）」
- **反例**：「RAG 于 2020 年由 Lewis 等人在论文中提出，引用量已超 8000 次…」（用未证明的数据开场）
- **出处**：p36-38、p52-53、p56、p59-63、p74-75、p303-304

## R10 关键句层优先归纳，慎用演绎

- **定义**：「在关键句层次，使用归纳推理比演绎推理更方便读者理解」（p305）。「归纳推理是把具有相似性的思想归类分组，根据各要点具有的共同性得出结论」（p305）。归纳的检验是「找到一个能够表示该组所有思想的名词……这个词必须是一个单一名词」（p102）。
- **判定问句**：① 关键句层能否用**一个单一名词**概括全组？② 组内是否存在与该名词不相称的项？③ 第二句是否在对第一句的**主语或谓语**作评述（是 → 那是演绎，在关键句层应改为归纳并列）？
- **失败签名**：一组中前两条并列，第三条突然变成「因此…」的结论句；或读者必须走完整个三段论才拿到回报。
- **修复动作**：删掉复述结论的第三条，整组改为归纳式并列（同 R5 单一名词）。
- **正例**：「①上下文在变大 ②检索有天花板 ③工程不划算」← 同属「三个原因」
- **反例**：「①长上下文是趋势 ②RAG 依赖长上下文 ③因此 RAG 会消失」← 演绎，且结论超出本组
- **出处**：p94、p96、p102-105、p168、p305

## R11 行动性 / 描述性思想分治

- **定义**：「概括行动性思想（介绍采取的行动、行为、动作、步骤、流程）时，应说明采取行动后取得的结果（效果、达到的目标）。概括描述性思想（介绍背景、信息）时，应说明这些思想具有的共同点的含义」（p145）。
- **判定问句**：① 该句主语是否为人或组织、谓语是否为可执行动词，且可前接「我们应该／我们将」？是 → 行动性，否 → 描述性。② 行动性：每条后能否补出「……以便产生____」且**空内为同一结果**？③ 描述性：能否找出共同点 → 确定**最小范畴** → 说明该共同点**隐含的意义**（p310）？
- **失败签名**：把步骤误当描述处理，导致无法排序；或行动结果写得不可判定——「你不能含糊地说：『我做这3件事是为了提高利润。』」（p148）
- **修复动作**：行动性→每条改写为「动词 + 可判定的结果（带数字/日期）」；描述性→先简化句子（只留主谓宾，删形容词副词）→ 合并同类项 → 再定顺序。
- **正例**：「把检索延迟压到 200ms 以内，以便让 RAG 能用在对答场景」（行动性，结果可判定）
- **反例**：「我们要提升检索能力」（结果不可判定）
- **出处**：p145-160、p166-173、p306-307、p310

# 呈现层 P1–P6（仅 detailed / mindmap 模式启用）

## P1 标题是完整断言，同组同句型

- **定义**：「标题应呈现某种思想、观点或论点，而不是只说明要讨论问题的类别」（p52）。「一组中的所有标题应该采用同样的句子顺序，即对仗」（p236）。「标题的作用是提示，而不是统领下文」（p236）。
- **判定问句**：① 每个标题是否为**含主谓的完整断言**（非名词短语）？② 同组各标题的**首个词性**是否一致？③ 每个标题是否 ≤12 字？④ 删掉全部标题后，正文是否仍然通顺（p236）？
- **失败签名**：「背景」「成本分析」「销售渠道」；或同组混排「任命一位全职的总经理 / 职权范围的问题」。
- **修复动作**：补上判断词改成断言；统一首词词性；标题后首句要能独立起句，不回指标题。
- **出处**：p52、p236-237、p256

## P2 一种标题 = 一个层次；层级 ≤3；每层不可只有 1 项

- **定义**：「不论采取何种格式，一种标题应该代表一个思想层次」（p235）。「每一层级不可能只有一项内容」（p235-236）。「通常情况下，没有必要在每一节标题下再设分支」（p237）。
- **判定问句**：① 每种标题样式是否只对应唯一的金字塔层级？② 是否存在某层级下只有 1 个标题（→ 删掉该层，内容上提）？③ 总层级是否 ≤3？
- **失败签名**：「三、方法」下面孤零零一个「3.1」；或四层标题每层只包住一两段，标题比正文还密。
- **修复动作**：删单丁层；砍到 ≤3 层。
- **出处**：p235-237

## P3 每组标题前先集中介绍该组

- **定义**：「每组标题应提前集中介绍……在大标题下应有一段话，集中介绍下面标题的主要内容」（p237）。「千万不要紧接着文章题目写每一章的标题」（p237）。
- **判定问句**：每组子标题之前是否有 ≥1 段引言，概括该组要证明的总论点？
- **失败签名**：H1 下面直接跳到 H2，H2 下面直接跳到 H3。
- **修复动作**：每组标题前插入「本组回答什么问题」的引导段。
- **出处**：p237

## P4 图表 / 卡片标题必须是答案，不是类别名

- **定义**：「制作图表幻灯片的诀窍是：确定你想用图表回答的问题，**把答案作为图表的标题**，然后选择最适合表现论点的图表样式。图表的标题一定要直接传递信息，要么用一个完整的句子，要么用一个含有动词的短语」（p260）。「『各地区利润份额』所包含的信息，要比『西部地区约占利润的一半』少得多」（p260）。
- **判定问句**：每张图／每张卡片的标题，是否是一个**完整句或含动词的短语**，并且**直接就是该图要证明的结论**？
- **失败签名**：标题是类别名或坐标轴名——「成本构成」「发展趋势」「对比表」。
- **修复动作**：先写「这图回答什么问题 → 答案是什么」，把答案原句搬上去做标题。
- **正例**：「西部地区约占利润的一半」
- **反例**：「各地区利润份额」
- **出处**：p256-257、p260-263

## P5 过渡承上启下，不做章节播报

- **定义**：「不要把两个章节在做什么连接在一起，而应该把它们说的内容，即主要思想观点连接在一起」（p245-246）。「从金字塔结构的前一部分中挑选一个词、一句短语或总结其中心思想，把它用在下一部分的起始句中」（p247）。
- **判定问句**：过渡句是否**复述了上一节的思想**并预埋下一节（而非「下一节将讨论…」）？
- **失败签名**：「本章探讨了 X 的必要性，下一章将探讨如何决定 X」。
- **修复动作**：改写成「仅有 X 还不够，还必须能判断哪些 X 该优先——」。
- **出处**：p245-248

## P6 抽象内容配骨架图；句子要可成像

- **定义**：「如果遇到一些难以想象的段落，而且提出的思想观点非常抽象，可以用骨架结构代替图像来说明」——「一种或几种几何图形……再加上箭头之类的东西表明方向和相互关系」（p270）。「尽量砍去其修饰成分，只留下最本质的核心内容，然后找出其中的重复部分」（p159）。
- **判定问句**：① 读完这段，读者脑中能否浮现出一个**可命名的画面或关系图**？② 抽象内容是否已给出「几何图形 + 箭头」的骨架图？
- **失败签名**：抽象名词堆叠、多层嵌套定语、无任何可成像关系。
- **修复动作**：①圈出全部名词 ②用箭头连出关系 ③把箭头改写成动词，写成主谓句。
- **出处**：p159、p268-273
