# 详细版（detailed）

## 你要解决的问题

用户已看过精简版，愿意花 3–5 分钟深入理解。
本模式是**完整金字塔**：序言 → 中心思想 → 关键句层 → 支撑层。

## 前序

1. 先读 `../pyramid-rules.md` 的 **R1–R11 和 P1–P6**
2. 按 `../source-discipline.md` 取材（**只用官方网页，不抓社交**）

## 输出结构

### 1. 序言（SCQA，2–4 句，放在最前）

```
**背景**：<读者已知的事实，把读者锁定在特定时空>
**冲突**：<这个事实里出现了什么问题/张力>
→ 本文回答：<一句话的中心思想>
```

硬规则（R9）：
- 背景和冲突**必须都是读者已知、不会质疑的事实**。需要数据/推导/引用才能成立的，下移到正文。
- 删掉冲突后读者还会问这个问题吗？如果不会 → 冲突无效，重写。
- 禁止在序言里塞图表、数据表、术语定义。

### 2. 中心思想（一句话，紧接序言）

单一中心思想，含判断动词，概括全文（R1）。

### 3. 关键句层（2–4 个 H2，这是骨架）

**每个 H2 小标题必须是完整断言句，不是话题标签。**（R2 + P1）

| ❌ 标签 | ✅ 断言 |
|---|---|
| 基本概念 | 它的价值不在检索，而在让答案可溯源 |
| 工作原理 | 三段流水线里，只有切分这步真正影响效果 |
| 局限性 | 检索质量是天花板，模型再强也补不回来 |

硬规则：
- 2–4 条（≤5），每条必须是**含主谓的完整句**
- 全部能用一个**单一名词**概括（R5）——通常按「三个关键判断」组织
- 同组首词词性一致、标题 ≤12 字（P1）
- 关键句层用**归纳**并列，不要用演绎三段论（R10）
- 顺序必须可标类型（R6）：默认「定义 → 机制 → 用途 → 当下/局限」= 结构序 + 程度序

### 4. 每个 H2 下面的支撑层

- **先写一段引导句**，说明这一组要证明什么（P3），不要直接甩 bullet
- 每条支撑必须回答该 H2 引发的疑问，**类型被疑问词锁定**（R8）：
  标题说「为什么」→ 支撑必须是**原因**；说「如何」→ 必须是**步骤**；说「你怎么知道」→ 必须是**证据**
- 每条至少 2 个 markdown 链接
- 层级 ≤3（P2），某层只有 1 项就删掉该层

### 5. 「当下在讨论什么」段（如有）

**必须拆成正方 / 反方两组**（R7 MECE），不要写成松散 bullet：

| 主张 | 反方 |
|---|---|
| 观点 A（出处） | 观点 B（出处） |

### 6. 过渡（P5）

段与段之间的过渡句，要**复述上一节的思想**并预埋下一节。
❌「下一节将讨论它的局限性」 ✅「但检索这一环并不总是可靠——」

## 硬规则汇总

- 每个事实断言带 markdown 链接，链接必须来自实际抓到的页面，**一个都不许编**
- 行话第一次出现时括号解释，如「embedding（把文字转成一串数字）」
- 素材不足某段 → 老实说「这部分公开资料不足」，不要硬凑（见 source-discipline 降级话术）
- 结尾**不要**写「希望对你有帮助」之类的套话
- 抽象内容配骨架图或用可成像的句子（P6）

## 收尾

输出后照 `../pyramid-audit.md` **全版 16 项**逐条审计。有 no 就重写该段。审计不展示给用户。
