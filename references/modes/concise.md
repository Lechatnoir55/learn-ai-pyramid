# 精简版（concise）

## 你要解决的问题

用户时间紧，30 秒扫一眼。但**「短」不等于「一句话」**。
一句话必然语无伦次，因为没有结构。本模式产出的是**微金字塔**——
麻雀虽小，结论层、关键句层、行动层一个都不能少。

## 前序

1. 先读 `../pyramid-rules.md` 的 **R1–R8**
2. 按 `../source-discipline.md` 取材（**只用官方网页，不抓社交**）
3. 取材后先做分组（R5 单一名词）和排序（R6），再动笔

## 输出格式（固定 4 行，总长 ≤320 字）

```
**先说问题**：…（可选，仅当这个概念自带明显矛盾/争议时才写，一行——把 SCQA 的冲突面压成一句大白话）

**一句话讲清**：<一句断言。必须含判断动词。禁止类比开场，禁止「XX 是一种…」定义句开场>

**三个事实**：①… ②… ③…（2–4 条，必须同属一个单一名词，显式标序，每条可接「因为」读通，互不包含）

**你的行动**：<你具体该做什么——一个可执行动作>

来源：[官方](url)
```

> 四段即金字塔的「纵向疑问/回答」：每段都是读者脑子里冒出来的问题，用答案接住。
> 标题用口语短词而非名词标签/疑问词——读起来不像填空模板，但结论先行、关键句层、MECE 一点未丢。

## 语气红线（说人话，别念白皮书）

结构对了还不够——读起来要像你**当面跟同事解释**，不像翻译机或厂商 PR。

- 用第二人称「你」称呼读者（讲架构细节时才转回第三人称）。
- 拒翻译腔 / 厂商腔词：「即插即用」「赋能」「落地」「生态」「对标」「认 MCP」这类，换成大白话（"直接能用""真能干活""不是 PPT 了""支持 MCP 吗"）。
- 短句为主，一句一个意思；砍掉长定语和排比堆叠。
- 比喻可用，但只能当断言的**辅助**——先给判断，再用比方帮理解；禁止「只打比方不给判断」。
- 自检一句：读给不懂技术的朋友，他会不会觉得你在掉书袋？会 → 重写。

## 逐行硬规则

### 「一句话讲清」行
- 必须是**断言**，不是定义、不是背景铺陈。判断动词要有（是/不是/会/不会/优于/取决于/只是…）。
- 比喻可用，但只能当断言的**辅助**——先给判断，再用比方帮理解；禁止「只打比方不给判断」。
- ❌「RAG 就像是给 AI 配了一个随身图书馆。」（只有比喻，读者拿不到判断）
- ✅「RAG 就像给 AI 配了个随身图书馆——它让模型答题前先查资料，不再只靠记忆。」（比喻辅助断言）
- ❌「RAG 是一种检索增强生成技术。」（定义句，不可争议，等于没说）
- ✅「RAG 只是过渡方案，长上下文成熟后它的必要性会下降。」

### 「三个事实」行
- 2–4 条，**必须同属一个单一名词**（问自己：这三条能一起叫「三个原因」吗？还是混入了一个步骤、一个案例？）
- 每条是**完整句**，不是名词。
- 显式标 ①②③。
- **互不包含**（MECE）。出现「其他」= 没想清楚，重写。
- 必须能标出顺序类型（时间/结构/程度）。打乱后无损 = 无序 = 重写。

### 「你的行动」行
- 落到**你**身上：你具体该做什么，给一个可执行动作。
- 不写「希望对你有帮助」这类套话。

### 「先说问题」行（可选）
- 只在概念自带明显矛盾时写。例如：官方宣称 A，但社区实测 B；或它解决了 X 却带来了 Y。
- 一行，给出冲突的两面，压成大白话。

## 明确禁止

- 禁止「不用标题、不用项目符号」的纯散文——那正是散架的根源
- 禁止纯比喻开场（只打比方不给判断 = 违规；比喻可作断言的辅助）
- 禁止「有三大优势」这类缺乏思想的概括（R3）
- 禁止无来源的事实断言
